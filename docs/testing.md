# Testing and reproducibility

## Automated checks

```text
uv sync --extra dev --python 3.12
uv run pytest
uv run ruff check app experiments k8s tests
```

The tests cover weighted averaging with a hand-calculated answer; stale,
duplicate, malformed and wrong-run replies; quorum loss; delayed-client rejoin;
strict synchronous behaviour; deterministic/disjoint data preparation; data
validation; Flower message roundtrips; quality metric definitions; and per-bank
deployment mounts.

The coordinator timing tests use a controlled clock and scripted arrivals. They
check behaviour without depending on machine speed.

## Quick software acceptance

1. Prepare a fresh synthetic dataset with `bank-fl prepare --synthetic`.
2. Run five healthy local rounds. `summary.json` should say `completed`, with
   five committed rounds and no unresolved requests.
3. Run the real local federation:

   ```text
   uv run bank-fl flower --rounds 8 --scenario slow --delay 25 --deadline 20
   ```

4. In `events.jsonl`, first confirm the selected bank was dispatched work in the
   fault attempt. A bank still busy with older work can miss that attempt; such a
   run does not test the configured fault. Choose a later fault attempt and rerun.
   Find the delayed attempt. It should commit with two valid
   banks before the delayed reply; that reply should later be rejected as stale.
   In a sufficiently long run, the delayed bank should contribute to a later version.
   Timing depends on the machine: increase the deadline and delay together if
   healthy client startup itself exceeds the proposed deadline.
5. Run `--scenario stale`; the selected bank's deliberately old version must be
   rejected. Run the unit tests for duplicate and invalid replies.
6. Run `--scenario unavailable --quorum 3 --startup-timeout 5`: the explicit
   result must be `startup_timeout`, with zero committed rounds.
7. Evaluate checkpoints and plot results. Synthetic plots must say they are
   software checks, not real fraud-detection evidence.
8. Repeat using the Kubernetes deployment and the separate fault-injection script.

The runtime returns a result directory even for a scientifically meaningful
failed experiment. Inspect `summary.json`; an exit code of zero alone does not
mean all requested rounds committed. Missing datasets, invalid inputs, failed
subprocesses and absent experiment summaries raise errors.

## Research protocol

- Obtain the real ULB dataset; record its source, checksum and terms.
- Prepare it once for each bank-count configuration and keep those partitions fixed.
- Run healthy pilots to choose a deadline, then freeze it.
- Use at least three seeds for the main modes and scenarios.
- Rotate the selected slow bank; log the exact fault attempt and duration.
- Use the same model, initialization seed, epoch count, batch size and learning rate.
- Keep failed runs. Compare completed rounds, elapsed time, processed examples
  and per-bank participation as well as model quality.
- Avoid tuning on the test curves. Fix thresholds using validation only.
- Report CPU/RSS sampling scope; host-wide counters from local processes cannot
  be treated as independent pod measurements.
- Record clock synchronization and censored recovery measurements.

`experiments/scenarios.yaml` provides a small repeatable matrix.
`python -m experiments.run --runtime flower` runs it serially to avoid resource
contention between experiments. Five-bank datasets are passed with `--data`;
the runner derives N and majority Q from their manifest.
